# 报修图片附件

日期：2026-09-07。新建报修可选上传报修部位图片；未选图片时保留原来的文字报修流程。

## 范围

- 每张工单最多6张图片，单张不超过5 MiB，支持JPEG、PNG、WebP静态图片。
- 提交前可预览、移除已选图片；成功提交后在工单详情查看缩略图并放大。
- HarmonyOS Web容器通过系统照片选择器提供选图入口；使用平板时需构建安装更新后的容器。
- 工单、初始处理记录与图片元数据一起提交；附件失败时不创建部分完成的工单。
- 图片读取使用工单权限：对应业主、本社区物业以及获派工单的维修人员。
- 服务器核验真实图片、纠正方向、移除附带元数据，并按最长边2560像素保存。图片只用于工单附件，不自动发送给AI。

## 接口与保存

有图片时使用 `POST /api/v1/repairs/with-images`，multipart中的 `data` 是报修JSON，`images` 是文件列表。无图片时继续使用原来的 `POST /api/v1/repairs`。

工单响应增加 `images`，每项包含图片编号、名称、类型、大小、尺寸、访问地址及创建时间。图片读取为 `GET /api/v1/repairs/{repair_id}/images/{image_id}`，请求必须携带当前登录凭据。

图片默认存放 `backend/uploads/repairs`，数据库保存关联信息。文件目录不公开托管，不纳入GitHub。备份应同时保留数据库及上传目录。

本轮只执行附件相关定向验证和必要构建；按当前要求同步源码到GitHub，全项目回归留到后续统一执行。
