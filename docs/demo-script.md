# 8–12 分钟演示脚本

## 演示前 2 分钟准备

从仓库根目录执行，确保状态可重复：

```powershell
npm --prefix frontend run build
backend\.venv\Scripts\python.exe backend\run.py --reset
```

浏览器打开 `http://127.0.0.1:8000`。三个账号密码均为 `123456`：`owner`、`property`、`maintenance`。

## 0:00–1:30 业主提交报修

1. 用 `owner / 123456` 登录，指出首页只保留三个高频服务、一个当前事项和一条公告。
2. 点击“报修”，再点“提交报修”。
3. 选择 `1号楼 1单元 101`、类型“水电维修”、优先级“紧急”。
4. 输入“厨房水龙头持续漏水”，提交并打开新工单，说明时间线从“待派单”开始。
5. 从右上角账户菜单退出。

## 1:30–3:00 物业派单

1. 用 `property / 123456` 登录，展示运营首页三个指标。
2. 打开“报修工单”，选择“水电维修”。
3. 点击“指派维修人员”，选择“陈师傅”，确认指派。
4. 指出状态和时间线同步更新，然后退出。

## 3:00–4:30 维修处理

1. 用 `maintenance / 123456` 登录。
2. 打开“水电维修”，点击“开始处理”。
3. 点击“完成工单”，填写“已更换水龙头阀芯并测试无渗漏”，确认完成。
4. 指出维修角色只能操作分配给自己的合法状态，然后退出。

## 4:30–6:00 业主确认与评价

1. 再次用 `owner / 123456` 登录并进入报修。
2. 打开“水电维修”，点击“确认完成”。
3. 点击“评价服务”，选择 5 星，输入“响应及时，处理专业”，提交。
4. 指出工单已走完 `提交 -> 指派 -> 处理中 -> 待确认 -> 待评价 -> 已完成`。

## 6:00–7:00 模拟缴费

1. 从“社区服务”进入“生活缴费”。
2. 打开“物业服务费”，点击两次“确认缴费”。
3. 展示服务端返回的 `DEMO-...` 支付参考号，强调客户端不提交金额，失败重试会复用同一幂等键。
4. 点击“完成”。这只是模拟支付，不发生真实扣款。

## 7:00–8:30 车位冲突与取消

1. 从“社区服务”进入“车位预约”，选择未来日期、`A-01`、`09:00 - 10:00` 并确认。
2. 点击“继续预约”，再次选择相同日期、车位和时段并提交。
3. 展示真实的“该时段已被预约”冲突，指出日期、车位和时段仍被保留，可直接修改。
4. 展开“我的预约记录”，取消刚才仍处于“预约中”的记录并确认。

## 8:30–10:00 公告发布与可见性

1. 退出业主，登录 `property / 123456`。
2. 打开“社区公告”，新建标题“中秋社区开放日”、内容“本周六上午十点开放邻里中心，欢迎居民参加。”的草稿。
3. 打开草稿并点击“发布公告”。
4. 退出物业，再登录 `owner / 123456`。
5. 打开“消息”，确认刚发布的公告和正文可见，说明业主看不到物业草稿。

## 备用与恢复

- 页面状态已被前一次演示使用：按 `Ctrl+C` 停止服务，运行 `backend\.venv\Scripts\python.exe backend\run.py --reset`，刷新浏览器。
- 提示缺少前端构建：运行 `npm --prefix frontend run build` 后重新启动。
- 端口 8000 被占用：运行 `backend\.venv\Scripts\python.exe backend\run.py --reset --port 8002`，改开 `http://127.0.0.1:8002`。
- 平板临时无法连接：先在电脑演示 `http://127.0.0.1:8000`，再按 [deployment.md](deployment.md) 检查同一 Wi-Fi、IPv4 和防火墙。
