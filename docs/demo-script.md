# 最终交付现场演示流程

更新日期：2026-09-07。建议时长约 12 分钟，设备使用横屏 HarmonyOS 平板模拟器。安装、启动及联网按 [DevEco Studio 平板模拟器指南](deveco-tablet-guide.md) 提前完成。

## 演示前准备

首次安装和下载镜像安排在演示之前。进入工程根目录，构建后用独立数据库开始一轮演示：

```powershell
Set-Location 'C:\Users\Lenovo\Desktop\harmonyos\smart_community\smart-community-web'
npm --prefix frontend run build
.\backend\.venv\Scripts\python.exe demo\run_demo.py --database .\backend\delivery-demo.db --reset
```

该命令清空指定的专用演示库。若需保留上轮记录，先备份或省略 `--reset`；重演前必须停止旧服务。

另开窗口检查：

```powershell
.\backend\.venv\Scripts\python.exe demo\check_demo.py --check-ai
```

确认“0 项失败”，模拟器已通过 HDC 映射加载 `http://127.0.0.1:8000`。三个账号分别是 `owner`、`property`、`maintenance`，密码均为 `123456`。

本场 AI 使用本机离线模拟草稿服务，按规则整理输入；缴费为模拟操作，不发生真实扣款。若使用真实模型，应提前按 [AI 配置](ai-assistance.md) 接入，并如实说明本场服务类型。

预先确定日期 D 为演示日后第 7 天，可运行 `(Get-Date).AddDays(7).ToString('yyyy-MM-dd')`。例如 2026-09-07 演示时 D 为 2026-09-14。预约和公告都使用 D，之后演示重新计算。

## 0:00 至 0:40：系统与业主首页

1. 用 `owner / 123456` 登录。
2. 展示首页的“报修”“缴费”“车位”，以及当前事项和社区公告。
3. 说明三类用户在同一社区数据上协作，并由角色权限控制可见入口和操作。

## 0:40 至 2:20：AI 整理报修并提交

1. 首页点“报修”，再点“提交报修”。
2. 房屋选择“1号楼 1单元 101”，先保留默认类型“公共设施”和优先级“普通”。
3. 输入“厨房水龙头持续漏水”，点“AI 整理”。
4. 查看建议：“水电维修”“普通”“厨房水龙头持续漏水。”；如出现待补充提示，再检查其中的信息。此时未采用，表单类型仍保持原选择。
5. 点“不采用”展示人工决定，再点“AI 整理”并“采用建议”。核对类型和描述变化，需要时可手动修改。
6. 点“提交报修”。打开新生成的“水电维修”工单，记住工单编号，展示“待派单”和处理记录。
7. 点详情右上角 X 关闭，再点右上角头像的“账户菜单”并“退出登录”。

讲解：AI 只提供建议，采用不等于提交；工单由业主明确提交后才创建。离线示例不会自动判断为“紧急”，需要时由操作者选择。

## 2:20 至 3:35：物业派单

1. 用 `property / 123456` 登录，展示运营首页的待处理工单、已完成工单和待收费用。
2. 导航进入“报修工单”，打开刚才记录编号对应的“水电维修”。
3. 点“指派维修人员”，下拉选择“陈师傅”，点“确认指派”。
4. 核对状态“已指派”及记录“已指派给陈师傅”。
5. 关闭详情，再退出登录。

## 3:35 至 4:50：维修处理

1. 用 `maintenance / 123456` 登录，进入“我的工单”。
2. 打开同一“水电维修”，点“开始处理”，状态变为“处理中”。
3. 点“完成工单”，填写“已更换水龙头阀芯并测试无渗漏”，在弹窗点“确认完成”。
4. 状态变为“待确认”。关闭详情并退出。

讲解：维修人员处理指派给自己的工单，完成后交由业主确认。

## 4:50 至 5:55：业主确认与评价

1. 再次登录 `owner`，进入“报修”，打开同一工单。
2. 在详情点“确认完成”，状态变为“待评价”。
3. 点“评价服务”，评分下拉框选择“5 星”，评价填“响应及时，处理专业”，点“提交评价”。
4. 展示“已完成”以及处理记录，关闭详情。

完整状态链：`待派单 -> 已指派 -> 处理中 -> 待确认 -> 待评价 -> 已完成`。维修弹窗和业主详情各有一次“确认完成”，对应不同角色的动作。

## 5:55 至 7:00：模拟缴费

1. “社区服务”进入“生活缴费”，打开待缴的“物业服务费”。
2. 初始账单为 `2026-09`、`268.00` 元；核对页面信息。
3. 在账单详情点“确认缴费”，打开“确认模拟缴费”弹窗。
4. 在确认弹窗再次点“确认缴费”，这次才提交支付请求。
5. 展示“缴费完成”和服务端生成的 `DEMO-...` 参考号，点“完成”。
6. 查看待缴列表更新，切换“已缴”可找到该账单。

两次按钮在不同弹窗层级，不是重复连点。正常演示不需要制造网络错误。响应丢失后的幂等重试由自动化测试验证；此处说明模拟缴费不发生真实扣款。

## 7:00 至 8:35：预约冲突与取消

1. “社区服务”进入“车位预约”，日期选 D，点“下一步”。
2. 选择 `A-01`，选择 `09:00 - 10:00`，点“确认预约”。
3. 看到“预约成功”后点“继续预约”。
4. 再选完全相同的 D、`A-01`、`09:00 - 10:00` 并确认。
5. 展示“该时段已被预约，请重新选择时段。”；核对日期、车位和时段仍保留，可直接修改。
6. 展开“我的预约记录”，找到本次日期、时段且状态为“预约中”的记录，点“取消”，在弹窗点“确认取消”。
7. 核对“已取消”。本轮没有其他演示记录时只有这一条活动预约。

## 8:35 至 10:30：AI 公告拟稿与发布

1. 退出业主，登录 `property`，导航进入“社区公告”，点“新建公告”。
2. 标题填“社区邻里开放日”。内容填“2026年9月14日上午10:00开放邻里中心，欢迎社区居民参加”，把日期换成本轮 D。
3. 点“AI 拟稿”，查看标题、正文和待补充信息，点“采用建议”。
4. 核对日期、地点和措辞。离线服务保留有效标题并整理句末标点，不展示为真实模型创作结果。
5. 点“创建草稿”，打开该公告，先展示“草稿”状态，再点“发布公告”。
6. 核对“已发布”。关闭详情，再退出登录。

讲解：生成、采用、创建草稿、发布是不同操作。AI 不直接创建或发布公告。

## 10:30 至 12:00：业主可见性与收尾

1. 登录 `owner`，进入“消息”，打开“社区邻里开放日”。
2. 核对完整正文和“已发布”。业主列表不显示物业内部草稿“内部排期草案”。
3. 回顾报修完成、缴费记录、预约取消和公告可见性，说明数据在服务端持久保存。
4. 需要留证时，分别保存工单处理记录、缴费结果、预约冲突和已发布公告的模拟器截图。

## 现场恢复

| 情况 | 操作 |
|---|---|
| 详情挡住账户菜单 | 先点右上角 X 关闭详情 |
| 左侧只显示图标 | 保持横屏，按图标提示定位；更窄时用左上角导航菜单 |
| 找不到新工单 | 按先前记录的编号和描述定位，不只看类型 |
| AI 暂不可用 | 保留当前输入并手动填写，后续按相同业务流程演示 |
| 预约无冲突 | 确认两次日期、车位、开始和结束时段完全一致 |
| 账单已经缴清 | 确认所用数据库；下一轮在备份后重置独立演示库 |
| 模拟器连接失败 | 检查电脑服务、设备连接和 HDC 映射，见模拟器指南 |
| 需要电脑备用演示 | 打开电脑 `http://127.0.0.1:8000`，明确说明此时为电脑浏览器展示 |

不使用固定旧日期，不在演示中关闭服务窗口，不把浏览器自动化结果称为 HarmonyOS 设备验收结果。
