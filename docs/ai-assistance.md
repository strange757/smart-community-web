# AI 辅助填写

当前提供两项可选能力：业主报修描述整理、物业公告拟稿。默认不启用云端调用。配置完成后，点击 AI 按钮才发送当前输入；建议需要人工采用，报修提交、草稿创建和公告发布继续走原有操作。

## 配置云端模型

模型服务须提供 `POST /chat/completions`，支持 `messages`、`response_format: {"type":"json_object"}`、`temperature` 和 `max_tokens`。模型需返回 `choices[0].message.content` 中的 JSON 文本及 `finish_reason: "stop"`。仅有同名模型或兼容接口地址，不保证支持上述全部参数，请按服务商文档确认。

配置文件固定为 `backend/.env`，从仓库根目录或 backend 目录启动均可加载。模板见 [backend/.env.example](../backend/.env.example)。如已有 `.env`，只追加或更新下面的 AI 配置，不覆盖其他设置。

```dotenv
COMMUNITY_AI_ENABLED=true
COMMUNITY_AI_BASE_URL=https://your-provider.example/v1
COMMUNITY_AI_MODEL=your-model-name
COMMUNITY_AI_API_KEY=your-api-key
COMMUNITY_AI_TIMEOUT_SECONDS=30
```

示例地址和凭据均为占位符，必须换成你使用的服务商提供的值。`BASE_URL` 填服务前缀，后端会追加 `/chat/completions`，不要重复填写该后缀。云端需要 HTTPS 和 API Key。环境变量优先于 `.env`；修改后需重启后端。

API Key 只放后端配置，不填写在前端文件、浏览器或 GitHub 仓库中。`.env` 已被 Git 忽略。模型服务按其自身规则计费。

在仓库根目录执行：

```powershell
npm --prefix frontend run build
backend\.venv\Scripts\python.exe backend\run.py
```

如果端口已占用，先结束自己原来的服务，或增加 `--port 8002` 并打开对应地址。新建独立演示库可增加 `--database backend\ai-demo.db`，无需删除旧数据。

## 业主：报修整理

1. 以 `owner` 登录，打开报修并点击“提交报修”。
2. 选择房屋，填写问题描述，例如“厨房水龙头一直漏水，关紧之后还是漏”。
3. 点击“AI 整理”，查看建议类型、优先级、整理后的描述和待补充事项。
4. 选择“采用建议”填入表单，或“不采用”保留原文。采用后仍可修改。
5. 检查内容后点击“提交报修”。生成建议本身不会创建工单。

## 物业：公告拟稿

1. 以 `property` 登录，进入社区公告并新建草稿。
2. 填写标题及公告要点，内容至少 4 个字符；没有标题也可生成。
3. 点击“AI 拟稿”，检查建议。缺少的日期、范围等应由物业补充。
4. 采用并修改后创建草稿，再在公告详情中执行发布。AI 不直接发布公告。

## 数据与异常处理

- 仅发送当前表单里的问题描述，或公告标题与内容，以及固定任务指令。不自动附加账号、房屋、账单或社区数据库记录。你自行写入文本的个人信息仍会随文本发送给配置的服务商。
- 只有业主能请求报修建议，只有物业能请求公告建议。两项接口均执行登录及角色校验。
- AI 不具备支付、查询全库、派单、修改状态或发布工具。返回字段、类型、长度会由服务端校验；这能拒绝格式错误，但不能保证内容事实正确，采用前仍需检查。
- 每用户每分钟最多 8 次调用尝试，限流为单进程演示级实现。默认超时为 30 秒，不自动重试付费请求。
- 未启用/未配置返回 503；超时 504；模型服务异常或草稿格式错误 502；频率过高 429。页面会保留输入，仍可手动填写。
- 编辑输入会作废当前建议；关闭弹窗后重新打开，不复用旧建议。模型返回的 HTML 按普通文本呈现。

## 验证边界

后端自动化测试通过受控 HTTP 响应检验模型协议、权限、超时、错误格式、限流和无业务写入。前端与浏览器测试检查人工采用、失败恢复和布局。浏览器中的成功生成测试使用明确标记的测试数据，不代表已经调用真实云端模型。

真实云端验收需要配置可用服务后，分别生成一份报修建议和公告草稿，核对供应商调用记录、内容质量、耗时及费用。当前未配置服务商凭据，尚未完成这一步。
